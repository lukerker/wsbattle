# 部署與設定

## 架構

```
瀏覽器（React）── WebSocket ──> 對戰伺服器（Render，Node）── 引擎（同一份程式碼）
     │                                  │
     └── Firebase Auth（登入）          └── 驗證 Firebase 登入 token（只需要專案 ID，不需要機密金鑰）
```

- **對戰在伺服器的記憶體裡進行**，不逐步讀寫資料庫。伺服器收到操作 → 呼叫引擎 → 依每個人的權限過濾 → 廣播。
- **Firebase 只負責登入**（之後加上牌組儲存），用免費方案，不需要綁信用卡、不需要 Blaze。
- 房間存在伺服器記憶體。伺服器重啟或休眠後，進行中的牌局會消失。**這是目前還沒做完的地方**：之後會把「種子＋雙方牌組＋所有操作」存起來，重啟後用引擎重播還原。

## 在自己電腦上跑（開發）

兩個終端機各跑一個：

```bash
npm run dev --workspace @ws/server
```

```bash
npm run dev --workspace @ws/client
```

打開 http://localhost:5173 。沒有設定 Firebase 時是「測試登入」：輸入名字就能進，**每個瀏覽器分頁是不同的玩家**，開兩個分頁就能自己對打；第三個分頁可以測觀戰。

手機測試：手機和電腦連同一個 Wi-Fi，用 `http://<電腦的區域網路 IP>:5173` 開網頁，伺服器網址會自動用同一個主機名稱。

## 設定 Firebase 登入（要你自己在網站上做）

1. 到 https://console.firebase.google.com 建立專案（不需要開 Google Analytics）。
2. 左側 **Authentication** → 開始使用 → **登入方式**，啟用：
   - **電子郵件／密碼**
   - **Google**（需要填一個支援電子郵件）
3. **專案設定**（齒輪）→ 一般 → 您的應用程式 → 新增 **網頁應用程式**（`</>`），取得 `firebaseConfig`。
4. 在 `packages/client/` 建立 `.env.local`（這個檔案不會進版本庫），填入：
   ```
   VITE_FIREBASE_API_KEY=...
   VITE_FIREBASE_AUTH_DOMAIN=...
   VITE_FIREBASE_PROJECT_ID=...
   VITE_FIREBASE_APP_ID=...
   ```
   這些都是公開的網頁設定，不是密碼。
5. 伺服器要知道專案 ID，才會改成要求 Firebase 登入：
   ```
   FIREBASE_PROJECT_ID=<同一個專案 ID>
   ```
6. Authentication → 設定 → **已授權的網域**：加入之後正式使用的網址（localhost 預設就有）。

設定完重開前端和伺服器，登入畫面就會從「測試登入」變成 Email 註冊／登入加 Google。

## 部署到 Render（免費方案）

1. 把專案推到 GitHub（私人 repo 即可；`cards/` 卡圖不會被推上去）。
2. Render → New → **Web Service**，選這個 repo：
   - Build Command：`npm install`
   - Start Command：`node packages/server/src/main.ts`
   - Environment：`NODE_VERSION=24`、`FIREBASE_PROJECT_ID`、`ALLOWED_ORIGINS`（前端網站的網址，多個用逗號分隔）
3. 前端另外部署（靜態網站，例如 Render Static Site 或 Firebase Hosting），建置時設定 `VITE_SERVER_URL=wss://<你的 render 網址>`。
4. 免費方案閒置 15 分鐘會休眠，重新喚醒約 1 分鐘。前端進網頁時會自動先喚醒伺服器，大廳會顯示「正在喚醒對戰伺服器…」。有連線時前端每 25 秒傳一次 ping，所以對局中不會休眠。

**卡圖**：`cards/` 是有版權的圖片，只在開發伺服器提供，不會打包到正式網站。正式環境沒有卡圖時會用文字卡面；要讓朋友看到卡圖，需要另外決定怎麼提供（見 CLAUDE.md 的版權段落）。
